# 基本設計書：日報の過去3日分遡り提出

## 1. 概要

日報提出画面において、当日分の日報しか提出できない現状の仕様を改め、
過去3日分まで遡って日報を提出できるようにする。

関連Issue: #1

## 2. 背景・課題

現在、日報は当日分しか提出できない仕様になっている。
現場での作業状況によっては、当日中に日報を提出できず、
翌日以降にまとめて提出したいケースがある。
しかし現状の仕様では当日分の日報しか提出できず、
未提出のまま履歴に残ってしまう。

## 3. 対象範囲

| 項目 | 内容 |
|---|---|
| 対象画面 | 日報プレビュー・提出画面（`/me/daily-report`） |
| 対象ユーザー | 従業員（EMPLOYEEロール） |
| バックエンドの変更 | なし（詳細は「5. 調査結果」を参照） |

## 4. 変更内容

### 4.1 日付切替UIの追加

- 画面上部に、日付を切り替えるためのUIを追加する
  - 前日ボタン（`‹`）：表示中の日付から1日前に移動する
  - 「今日に戻る」リンク：当日以外を表示しているときのみ表示し、押下で当日に戻る
- 選択可能な範囲は「当日〜3日前まで」とする
  - 3日前より過去には、前日ボタンが無効化され、それ以上遡れないようにする
  - 未来日は選択できないようにする（翌日ボタンは設けない）

### 4.2 表示内容の切り替え

- 選択した日付に応じて、以下の内容が切り替わる
  - 現場ごとの実績テーブル（現場名・到着・離脱・作業時間）
  - 合計作業時間
  - 特記事項欄
  - 提出済みバナー（選択日の日報が既に提出済みの場合に表示）
- 提出ボタン押下時は、選択中の日付を対象として日報を提出する

## 5. 調査結果（本仕様に至った根拠）

既存コードを調査した結果、以下が判明した。

- バックエンド（`DailyReportService`, `MeController`等）は、`workDate`を
  自由に指定できる作りになっており、「当日限定」という制約はコード上存在しない
- フロントエンド（`me/daily-report/page.tsx`）で `date` が
  `const date = todayString();` という固定値になっており、
  これが実質的な「当日しか送れない」制約の直接の原因だった
- `me/routes/page.tsx`（本日のルート画面）に、日付切替の実装が
  既に存在していたため、同じパターンを日報画面にも適用する方針とした

上記より、**バックエンドの変更は不要**と判断した。

## 6. 「3日前まで」とした理由

前日のみとする案もあったが、現場の実態
（体調不良や通信環境等により、翌日中の提出も難しいケースがある）
を踏まえ、3日前までの提出を許容する方針とした。
なお、この期間設定は運用開始後に見直す可能性がある。

未来日を選べないようにするのは、日報が「その日の作業実績」を
記録するものであり、まだ発生していない未来日の実績は
概念的に存在しないためである。

## 7. 影響範囲

- `frontend/src/app/(employee)/me/daily-report/page.tsx` のみ
- `docs/requirements/frontend.md` の日報画面の仕様記述
  （「当日の」という記述の見直しが必要。PR作成時に他の変更ファイルと
  合わせて整合性を取る）
