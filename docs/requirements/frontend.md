## デザイン仕様

### コンセプト

消防設備の点検業務を支える「キッチリした業務システム」。ただし退屈にならないよう、
深いネイビー×ブルーのグラデーション、ステータスの色分け、タイムライン表現などで
視覚的なリズムを付ける。イメージカラーは**青**。

### カラーテーマ（tailwind.config.ts に追加）

ライトテーマ基調。チャート色はCVD検証済みパレットを使用する。

```ts
colors: {
  // ブランド（青系）
  brand: {
    DEFAULT: '#1d4ed8',   // メインの青（ボタン・アクティブ状態）
    hover:   '#1e40af',
    light:   '#dbeafe',   // 選択背景・バッジ背景
    faint:   '#eff6ff',   // ホバー背景
  },
  // サイドバー・ヘッダー（濃紺）
  navy: {
    DEFAULT: '#0c1e3e',
    light:   '#16325f',
    border:  '#1e3a6e',
  },
  // 背景・ボーダー
  surface: {
    page:   '#f4f7fb',    // ページ背景
    card:   '#ffffff',    // カード背景
    border: '#e2e8f0',
  },
  ink: {
    DEFAULT:   '#0f172a', // 本文
    secondary: '#475569',
    muted:     '#94a3b8',
  },
  status: {
    success: '#059669',   // 完了・良
    warning: '#d97706',   // 作業中・注意
    danger:  '#dc2626',   // 不良・エラー
  },
  // チャート専用（検証済みパレット。系列は最大3色まで）
  chart: {
    s1: '#2a78d6',        // 系列1（青）
    s2: '#eb6834',        // 系列2（オレンジ）
    s3: '#1baf7a',        // 系列3（アクア）
    grid: '#e1e0d9',
    axis: '#898781',
  },
}
```

### レイアウト

- **管理者**: 左サイドバー（幅240px固定・`navy` 背景に白テキスト、上部にロゴ+システム名）
  + ヘッダー（ページタイトル・ユーザー名・ログアウト）+ メインコンテンツ
  - アクティブメニューは `brand` の左ボーダー+明るい背景でハイライト
- **従業員**: モバイル前提の1カラム（max-w-lg 中央寄せ）。上部に濃紺ヘッダー、
  下部に固定タブナビ（ルート / 日報）。PCでも同レイアウトで違和感がないこと
- カードは白背景 + `border-surface-border` + `rounded-xl` + ごく薄いshadow
- インタラクション要素には `transition-all duration-200` を付与する
- フォントは `next/font/google` の Noto Sans JP を使用する

### ステータス表現（Badge）

| 状態 | 表示 | 色 |
|-----|------|-----|
| NOT_STARTED | 未着手 | グレー |
| IN_PROGRESS | 作業中 | `status.warning`（琥珀） |
| COMPLETED   | 完了   | `status.success`（緑） |
| 点検結果 PASS | 良 | 緑 |
| 点検結果 FAIL | 不良 | `status.danger`（赤） |
| 点検結果 NA   | 対象外 | グレー |

色だけに意味を持たせず、必ずテキストラベルを併記する。

## 画面仕様

### ログイン `/login`

- 濃紺のグラデーション背景に中央配置のログインカード（盾/炎のアイコン+システム名）
- メールアドレス・パスワード入力フォーム
- ログイン成功後、ロールに応じて `ADMIN → /admin/dashboard`、`EMPLOYEE → /me/route` へ
- エラー時はカード上部に赤いエラーメッセージを表示

### 【管理者】ダッシュボード `/admin/dashboard`

- 日付セレクター（デフォルト当日）
- サマリーカード4枚: 出動職員数 / 予定現場数 / 完了現場数 / 日報提出数
  （完了現場数は「12 / 18」のように予定数との対比で表示）
- 職員別の当日状況テーブル（進捗バー付き: 完了現場数/担当現場数、現在の作業現場、日報提出済みか）
- グラフ2種（recharts使用。チャート色は `chart.s1` 系列を使用）
  - 直近7日の点検実施状況: 縦棒グラフ（予定=薄青 `#9ec5f4`、完了=`chart.s1`。凡例+ツールチップ必須）
  - 不良指摘の設備カテゴリ別件数: 横棒グラフ（単一系列 `chart.s1`。件数を直接ラベル表示）
- グラフの軸・グリッドは `chart.axis` / `chart.grid` の控えめな色にする

### 【管理者】ルート設定 `/admin/routes`

- 上部で職員（EMPLOYEEのみ）と日付を選択
- 選択中の日のルートを訪問順リストで表示。以下の操作ができる:
  - 現場マスタから現場を検索して末尾に追加
  - 並び順の変更（上へ/下へボタンで十分）
  - 削除（作業開始済みはAPIが400を返すのでエラーメッセージを表示）
  - 各現場への指示メモ入力
- 「保存」で `PUT /admin/routes`（丸ごと置き換え）
- 「期間一括設定」ボタン → モーダルで開始日・終了日・土日スキップを指定して
  `POST /admin/routes/bulk`（同じ現場に1週間通うケース用）
- 各行に現場の住所・ステータスBadgeを表示

### 【管理者】職員マスタ `/admin/staff`

- 一覧テーブル（名前・メール・ロール・有効/無効）
- 新規登録・編集はモーダルフォーム（編集時パスワードは空欄なら変更しない）
- 削除は確認ダイアログ後に論理削除

### 【管理者】現場マスタ `/admin/sites`

- キーワード検索付き一覧テーブル（現場名・住所・建物用途・担当者・電話）
- 新規登録・編集はモーダルフォーム、削除は確認ダイアログ後に論理削除

### 【管理者】点検項目マスタ `/admin/items`

- 設備カテゴリごとにグループ化した一覧（display_order順)
- 新規登録・編集はモーダルフォーム（カテゴリ・点検内容・表示順）

### 【管理者】日報一覧 `/admin/daily-reports`

- 日付・職員フィルター
- 職員ごとの日報カード: 現場ごとの到着/離脱/作業時間テーブル+合計時間+特記事項
- 各現場行から点検報告詳細 `/admin/reports/[assignmentId]` に遷移できる

### 【管理者】点検報告詳細 `/admin/reports/[assignmentId]`

- 現場情報・作業時間のヘッダー
- カテゴリごとの点検結果一覧（良/不良/対象外のBadge、不良は行を赤系背景で強調、指摘メモ表示）
- 全体所見（remarks）

### 【従業員】本日のルート `/me/route`

- 日付切替（前日/翌日矢印+日付表示。デフォルト当日）
- 進捗サマリー（「3現場中 1現場 完了」+進捗バー）
- **縦タイムライン**で訪問順に現場カードを表示:
  - 訪問順の丸数字をタイムラインのノードにし、完了=緑チェック・作業中=青パルス・未着手=グレー
  - カード内: 現場名・住所・建物用途・管理者メモ・ステータスBadge・到着/離脱時刻
  - タップで `/me/visits/[id]` へ
- 全現場完了時は日報提出への導線バナーを表示

### 【従業員】現場作業画面 `/me/visits/[id]`

作業の流れが一目で分かるステップ表示（① 到着報告 → ② 点検入力 → ③ 離脱報告）。

- **未着手**: 現場情報カード+大きな「到着報告」ボタンのみ
- **作業中**: 点検フォームを表示
  - 設備カテゴリごとのセクション（アコーディオン開閉可）
  - 各項目は 良 / 不良 / 対象外 の3択セグメントボタン+備考入力（不良時は備考を促す）
  - 全体所見（remarks）テキストエリア
  - 「一時保存」ボタン（PUT。何度でも保存可）
  - 未入力項目数を画面下部に固定表示し、「カテゴリ内を一括で『良』にする」補助ボタンを付ける
  - 保存済みになると「離脱報告」ボタンが有効化
- **完了**: 点検結果の読み取り専用表示+作業時間

### 【従業員】日報 `/me/daily-report`

- 当日の現場ごとの実績テーブル（現場名・到着・離脱・作業時間。時間はAPI計算値を表示）
- 合計作業時間の強調表示
- 特記事項テキストエリア
- 「日報を提出」ボタン → 確認ダイアログ → 提出後は読み取り専用+提出済みバナー
- 未完了の現場がある場合は警告を表示（提出自体は可能）

## APIクライアント設計

- `lib/api.ts` でaxiosインスタンスを作成し、すべてのAPIコールはここ経由で行う
- リクエストインターセプターで `Authorization: Bearer <token>` ヘッダーを自動付与する
- レスポンスインターセプターで401エラーを検知したらリフレッシュトークンで再取得を試み、
  それも失敗したら `/login` にリダイレクトする
- トークンは `localStorage` に保存する
- APIエラーは `error.response.data.detail`（日本語）をそのまま画面に表示する

## 認証フロー

- 未認証ユーザーが `(admin)` / `(employee)` 配下にアクセスした場合は `/login` にリダイレクト
- EMPLOYEEが `/admin/**` にアクセスした場合は `/me/route` にリダイレクト（逆も同様）
- `useAuth` フックで認証状態・ロールをグローバル管理する
